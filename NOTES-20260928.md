## Themes

### 1. Type names are resolved in the parser, one file at a time → #4, #11, part of #16

- `named_type` (`src/parser/mod.rs:5839`) resolves a type name while parsing. For an
  undeclared name it returns a placeholder `Nominal { name, backing: TypeVar(u32::MAX) }` and
  **drops the arguments**. The code's own comment ("ponytail") admits this.
- Each local module gets its own `Parser` (`src/run.rs` ~170-190), so an imported
  parameterised type is always a placeholder in the importer (#4). A forward reference in the
  same file is the same bug (#11).
- The checker's `expand` (`src/types/checker.rs:326`, via `placeholder_target`) swaps the
  real declaration in later, but its params stay unbound, so literals default to Dec.
- `nominal_params` is already collected by the parser and passed to the checker
  (`run.rs:227`, `checker.rs:380`). That's the hook for substituting args.

### 2. No name-resolution pass; names are flat strings → #16, #17, #24

- Members are global strings like `"Set.insert"`. The compiler (`Compiler::resolve`,
  `src/vm/compile.rs:1131`) and the checker each apply their own lookup order.
- #16: a user `Set` collides with the Builtin `Set`, which is loaded via `needed_by`.
- #17: a bare name finds the top-level global before `Owner.name`.
- #24: `predeclare` (`checker.rs:186`) only pre-binds *annotated* top-level names. Bodies
  are then checked in file order, so an unannotated `later = 1` is defaulted before
  `total : U64 = 30 + later` can constrain it.
- The README's known ceilings include the same shape of problem: `var` names are tracked
  in one flat set.

### 3. The checker exports narrow side tables, not types; the runtime fills the gaps → #6, #9, #14

- The only way into the compiler is `vm::compile::Unit` (built in `run.rs` ~320-420):
  `integer_binops`, `dec_literals`, `f32_literals`, `u128_literals`, `fractional_literals`,
  `conversions`, `coerce_values`, `coerce_params`, `match_types`, `dispatch_modules`, … Each
  was added when the VM needed one more bit. **There is no `NodeId -> Type` map.**
- Where the checker can't decide statically, the VM converts at run time
  (`coerce_values`/`coerce_params`, `checker.rs:1777-1790`; consumed at `compile.rs:485,512`),
  and nominals are erased at runtime (told apart by shape). That's the root of #9 (an erased
  `Code` looks like a raw int, so conversion repeats forever) and very likely #6 (a wrapper or
  conversion keeps the list's `Rc` from being unique).
- #14: `TYPED_MEMBERS` (`src/builtin.rs:441`) covers only Dict/Set/Str/List. The fork already
  has a patch (`member_of` table).
- An interpreter can live with runtime fallbacks. A Rust/Codex emitter can't: it needs every
  node's static type.

### 4. A real gap in type inference → #13

- Open tag unions have no row variables (`Type::TagUnion { tags, open }`, `src/types/mod.rs:80`),
  so unifying `[A, ..]` with `[B, ..]` succeeds but grows neither side. It needs a genuinely
  new piece of the type system.

## Retrofit estimates (cheapest / highest leverage first)

| Fix | Issues | Effort / notes |
|---|---|---|
| Record each node's type in `synth`/`check`; at the end apply the substitution and `defaulted`; export as `HashMap<NodeId, Type>` through `Unit` (or a sidecar dump) | Unblocks the Rust/Codex backends generally | **Small-medium.** Mostly a wrapper around `synth`/`check` (`checker.rs:2038`, `:636`). `self.literals` already does this for literals. Beware the loop over Let chains (statements are walked iteratively, not recursively). Doesn't fix wrong types, but you'd see every one. |
| Add `args: Vec<Type>` to `Type::Nominal`; the parser keeps unresolved names *with* args; `expand` substitutes `nominal_params` at resolution | #4, #11 | **Medium.** About 83 `Type::Nominal` sites (61 in checker.rs, 8 compile.rs, 5 parser, 3 layout.rs, 2 builtin.rs, 1 abi.rs, 3 types/mod.rs). Expanding lazily in the checker (it already has the `seen` recursion guard) should avoid the stack overflow the earlier eager "seed second parse" attempt hit on `Iter(a)`/`Step(a)`. |
| Check unannotated top-level names in dependency order (PR #22 computes the order), or pre-bind them to fresh type vars in `predeclare` | #24 | **Small.** |
| Try/Json signatures through a `member_of` table | #14 | **Small.** The fork's patch exists. Open question: `t.map_ok(f)` (method form) still wouldn't be typed. |
| Put the namespace's own members first in both lookups (compiler `resolve` + checker) | #17 | **Small**, as a local fix |
| A real resolver pass: unique symbol per binding, consumed by both checker and compiler | #16, #17, the `var` problem | **Medium-large.** The proper fix for theme 2. |
| Make literal conversions fully static, then delete `coerce_*` | #6, #9 | **Medium.** Depends on the rows above: every literal's type must be known first. |
| Row variables for open tag unions | #13 | **Large.** About 114 `TagUnion` sites (41 in checker.rs alone) and a change to how unification works. |

## Recommendation

Do these three first:
1. The `NodeId -> Type` export. It shows exactly where the checker's knowledge runs out, and
   the Rust/Codex emitters can consume it directly.
2. Type args on `Nominal` (#4, #11).
3. Dependency-ordered top-level checking (#24).

Postpone the resolver pass and row variables until the node-to-type table shows how much
Codex/Rust output they actually affect.
